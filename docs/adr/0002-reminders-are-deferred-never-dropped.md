# 提醒只会迟到、不会消失：心流与游戏状态下顺延并补发，游戏中仅以声音提示

v0.1 在心流（Flow）和游戏（Gaming）状态下把到点的提醒直接丢弃并重置计时器（`main.rs` 中的空分支 + `reminder.reset()`），导致重度键盘用户和全屏游戏玩家几乎永远收不到提醒——这是“效果不佳”的第一根因（docs/research/01-source-audit.md P0-1、P0-2）。v0.2 确立一条架构规则：**上下文只能改变提醒的投递时机和形态，不能取消提醒**。具体为：心流中到点 → 顺延到输入停歇 8 秒后投递完整提醒；游戏中到点 → 立即只播提示音（spec F5 的原意），视觉部分顺延，退出全屏后补发一次轻提示；离开时计时暂停而非重置，离开时长 ≥ 短休息时长视为已休息。

## Considered Options

- 保持“上下文中不提醒”：等价于让最需要护眼的场景（长时间打字、打游戏）完全失去保护，与产品目标相悖。
- 游戏中也弹视觉提醒：独占全屏下任何窗口都可能导致游戏被切出，是竞品被卸载的首要原因（Stretchly issue #355 六年未解，见 docs/research/03-competitor-ux.md）。

## Consequences

- “顺延（Defer）”成为领域概念，与用户主动的“延后（Postpone）”严格区分（见 CONTEXT.md）。
- 计时器需要区分“重置”“暂停”“顺延中”三种状态；`should_remind` 到点后不再由分支决定是否 reset，而是由投递结果决定。
