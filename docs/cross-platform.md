# EyeFlow 跨平台原生改造（开发预览）

## 保留的产品思想

EyeFlow 不是固定墙钟闹钟：它关注实际持续用屏、允许心流顺延但不丢提醒、短长两级休息、本人可推迟或跳过、离线保存状态。Windows 原版保留；公共 Rust 调度器通过 C ABI 供原生宿主使用，不引入账号、遥测或网页后台计时器。

手机应监测经用户同意选定的阅读/短视频等 App，而非假定手机整天都在使用。锁屏期间不累计用屏、不发休息提醒。平台拿不到信号时应停止或明确降级，不能伪造“自动识别”。

## 目录与职责

- `src/`：原 Windows 程序，保留现有托盘、Win32 检测与 UI。
- `crates/eyeflow-core/`：保留桌面调度器，并为手机提供显式观察状态的连续使用引擎；公共配置、C ABI、状态快照。手机不再把未选 App 或权限丢失当作桌面空闲。
- `mobile/android/`：Kotlin 原生客户端、JNI 桥接、用户启动的会话服务，目标 App 白名单与主动 Usage Access 授权。
- `mobile/ios/`：SwiftUI 自愿前台休息；旧累计监测与自动遮罩已停用，跨 App 连续检测暂不支持。
- `desktop/portable/`：macOS/Linux/Windows 可移植前台会话预览；它没有冒充系统全局检测。

## 平台差异是产品边界

| 能力 | Windows 原版 | Android 新客户端 | iOS 新客户端 |
|---|---|---|---|
| 自动键盘心流/全屏 | 原实现 | 不采集键盘；目标 App 识别 | 不采集其他 App 内容/键盘 |
| 用户选择目标 App | 未改动原桌面策略 | 使用情况访问权限 + 白名单 | 连续监测未提供 |
| 锁屏静默 | 原桌面策略 | 屏幕交互/锁定信号门控 | 不安排后台休息通知 |
| 连续目标使用 | 不适用 | 独立状态与已观察区间，见连续使用设计 | 不支持，不能以每日累计替代 |
| 提醒 | 原实现 | 渐进通知；独立授权并开启后可用10秒小卡，绝不自动全屏 | 自愿的应用内休息 |
| 离线/无账号 | 是 | 是 | 是 |

旧预览中的 iOS 每日累计阈值不符合连续用眼需求，不能视为可接受的降级。该入口及自动遮罩触发停用，应用启动清理旧监测和本应用的遮罩。FamilyControls / DeviceActivity 的累计阈值与 ManagedSettings 遮罩能力本身不能证明锁屏已持续足够久。只有找到受支持、可验证的连续使用/锁屏证据链后，才能重新提供跨 App 自动功能；Xcode 编译、签名和 entitlement 只是必要的工程条件，不会填补产品语义缺口。

Android 的常驻会话状态通知用于系统前台服务要求，与休息提醒区分；应保持静音，不以全屏 intent、覆盖层或无障碍权限强迫用户休息。Android 厂商省电、强制停止与撤销权限均可能中断服务，应在 UI 中可见，不承诺无法保证的送达。

## 验证与发布

各客户端 README 记录准确构建命令和前置条件。Linux 云机可以验证 Rust 与源码，但 iOS 真机构建要求 macOS/Xcode、签名及 entitlement。仅有源码、编译检查或单元测试不能标记为真机验收通过。

本次改动不自动上传 GitHub、不创建发布、不改账号安全设置、不申请手机系统权限。权限由 App 内解释后用户主动授予。
