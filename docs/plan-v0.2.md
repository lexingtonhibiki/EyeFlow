# EyeFlow v0.2 实现计划（内部工作文档）

> 依据：docs/research/01~06 六份调研、docs/adr/0001~0006 决策、CONTEXT.md 词汇表。
> 目标：把 v0.1“一声哔”的空壳，变成有完整“预告 → 休息 → 结算”闭环、真正懂上下文的护眼工具。

## 2. 架构（ADR-0006，实测后修订）

- 主线程平时跑无窗口、无 GL 的轻量循环（`PeekMessageW` 泵 + 200 ms 轮询）；只在需要显示窗口时进入 eframe 0.36（glow）会话，窗口全部关闭后会话结束、GL 释放。实测：空闲 ~16 MB；常驻 eframe 方案在 NVIDIA 机器上要 ~200 MB，已否决。
- 会话内根视口是屏幕外 1×1 锚点；预告浮窗 / 休息面板 / 设置窗都是子视口；浮窗每次新建窗口（`with_active(false)` 仅首次显示生效）并加 `WS_EX_NOACTIVATE`。
- 托盘（tray-icon）与热键（global-hotkey）在主线程启动时创建；`Runtime::step` 在两种模式下推进同一份逻辑。
- 键盘钩子线程保留自有 GetMessage 泵，只发时间戳（过滤自动重复与修饰键）；传感器线程 1 Hz 采样（空闲毫秒、全屏、可打扰性）。
- 会话期间外部线程通过全局 `egui::Context` 句柄 `request_repaint()` 唤醒 UI。

## 3. 调度核心（`core.rs`，纯逻辑，可单元测试）

- 短休息计时器：`due = now + 三角分布(min..max)`，默认 15~25 分钟（峰值 20）。
- 预告提前 15 s（长休息 30 s）。
- 用屏累计：空闲 < 30 s 视为活跃并累计；≥ 2 h 时下一次短休息升级为长休息（15 min）。
- 离开（空闲 ≥ 180 s）：计时暂停；返回时若离开 ≥ 休息时长则视为自然休息并重置计时；离开 ≥ 15 min 用屏累计归零。
- 心流：30 s 滑窗按键数 ≥ 阈值（低 40 / 中 70 / 高 100，已过滤 autorepeat）；到点后等最后按键 8 s 再投递。
- 游戏 / 不可打扰（SHQueryUserNotificationState ≠ ACCEPTS 或前台窗口全屏无标题栏）：到点只播声音，视觉顺延，恢复后补发。
- 用户动作：延后（每次提醒限 1 次，+5 min）、跳过、立即开始、完成；长休息不可延后、跳过后 10 min 再提示。
- 暂停 1 小时 / 免打扰时段：期间不投递，结束后若已到点则 60 s 后投递。
- 统计：今日完成（短/长/自然）、跳过、延后、连续天数；跨日滚动。

## 4. 界面

- 预告浮窗（屏幕右下角，约 360×150）：文案“{N} 秒后休息一下”，按钮 [现在开始] [延后 5 分钟] [跳过]。
- 休息面板（屏幕居中，约 460×320）：大倒计时、一条权威贴士（AOA/AAO 文案轮换）、按钮 [继续工作]（计跳过）；倒计时结束自动完成 + 结束音。
- 严格模式：休息面板改为全屏暗色遮罩（默认关）。
- 设置窗：分组卡片（提醒节奏 / 休息内容 / 声音 / 上下文 / 系统），min≤max 联动、时间下拉校验、恢复默认、开机自启（读写 HKCU\Run）、今日统计与“立即休息”。
- 托盘：左键/双击打开设置；菜单：打开设置（默认）、启用提醒（勾选）、立即休息、暂停 1 小时、静音、退出；tooltip 显示状态与下次休息时间。
