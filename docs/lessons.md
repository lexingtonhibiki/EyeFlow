# 踩坑回顾与设计经验（v0.1 → v0.5）

> 2026-09-17 · 从一个"只响一声"的 v0.1 空壳到可发布的 v0.5.0，把这一路踩过的坑和沉淀的设计原则集中记录，供后续维护者（包括未来的自己和 AI 协作者）参考。证据级细节见 docs/research/01~08、docs/adr/0001~0006、docs/report-v0.2~v0.4。

## 一、产品级踩坑：为什么 v0.1 "效果不佳"

教训的起点不是参数，而是**核心链路根本没有闭环**：

1. **"最后一公里"没有验收就当作完成**。系统通知是 `log::info!` 占位、护眼 25 秒没有任何载体、全局热键从未注册——spec 写了、任务清单打了勾、`#[allow(dead_code)]` 把编译器告警也压住了，但用户视角里这些功能不存在。
   → 对策：v0.2 起，每个功能按"用户能看到/听到什么"验收；不允许用 allow 压死代码告警来粉饰。
2. **上下文感知把"提醒"变成了"消失"**：心流和游戏状态下，到点的提醒被空分支吞掉还顺手重置计时器——越专注的人越收不到提醒，与产品目标完全相反。
   → 对策：ADR-0002 确立"上下文只能改变投递时机与形态，不能取消提醒"，并有 12 个调度核心单测锁住该规则。
3. **单信号判定不可靠**：只用键盘判"离开"（鼠标用户被误判）、只用窗口尺寸判"全屏"（自动隐藏任务栏误判）、只用 QUNS 判"不可打扰"（本机长期谎报 D3D 独占）。
   → 对策：多信号交叉佐证（QUNS 忙碌类 + 矩形佐证 + 输入空闲），且**必须排除自己进程的窗口**——我们自己的全屏边缘渐暗层会触发全屏检测，把自己误判成游戏。
4. **默认值拍脑袋**：心流阈值 10 键/30 秒 = 0.33 键/秒（任何打字都算心流）；间隔 10~18 分钟无出处。
   → 对策：ADR-0001 用 AOA 指南 + RCT 重新锚定默认值；伪需求（蓝光过滤、强制锁定）有 Cochrane/AAO 背书后才敢"不做"。
5. **环境差异是隐藏放大器**：同一份代码，在本机因 QUNS 长期谎报 D3D 独占，视觉提醒被永久静音——"效果不佳"在特定机器上被环境放大数倍。
   → 对策：可打扰性判定加矩形佐证；日志落在 `%APPDATA%\eyeflow\eyeflow.log`，出问题先看日志。
6. **状态机与真实使用节奏的边界**：看视频不动鼠标 3 分钟被判"离开"（与 Stretchly/LookAway 一致的有意取舍）；睡眠时间被 Windows 计时算进 dt，开盖瞬间轰炸预告。
   → 对策：离开=计时暂停 + 进入即记自然休息；dt > 10 分钟按离席归来处理。

## 二、架构级经验

### 2.1 后台工具的内存模型："无窗口时零 GUI"

最初 v0.2 试图常驻 eframe，实测在 NVIDIA 机器上一个空窗口就占 163 MB 私有内存、常驻 203 MB——与被用户诟病的 Electron 同量级。最终改为**轻量循环（无窗口、无 GL）⇄ 按需 eframe 会话**：空闲 16 MB，只在显示浮窗/设置时短暂进入 UI 会话（ADR-0006）。

经验：
- **先测再定架构**。"数十 MB"的假设被一台机器实测推翻；桌面 GUI 框架的常驻成本大头是 GPU 驱动，不是你的代码。
- eframe 的 `run_and_return` 支持同线程反复进出事件循环，这是"按需会话"得以成立的关键。
- 常驻托盘/热键必须在运行 Win32 消息泵的线程上创建；轻量循环用 `PeekMessageW`、会话期由 winit 泵，两模式共用同一份 `Runtime::step`，**保证窗口开不开、功能都不停摆**。

### 2.2 并发与事件：单一泵 + 事件总线

键盘钩子线程（自带 GetMessage 泵）、传感器线程（1 Hz）、托盘/热键（全局 channel 轮询）全部通过事件总线进入主线程；UI 会话期额外用全局 `egui::Context` 句柄唤醒。**同一条 `Runtime::step` 在两种模式下执行**，杜绝"开设置窗就冻结一切"的 v0.1 缺陷。

### 2.3 UI 宿主的视口细节（egui 0.36 + winit 0.30）

> 追记（v0.5.2）：预告期“边缘渐暗”先后经历两种实现（分层 GL 视口窗 → 闪烁；原生静态窗 → 无闪烁但用户反馈影响性能），最终**整个功能被移除**。教训：四条全屏宽度的合成层窗口（即便是静态的）在桌面合成器里仍产生可见的合成开销与视觉干扰，“余光可感”的收益抵不过用户对性能/干扰的感知——预告浮窗本身已经足够。

- 子视口一帧不被 `show_viewport_immediate` 使用即被销毁——浮窗每次出现换新 `ViewportId` 重建，正好绕过 **winit 的 `with_active(false)` 只在首次显示生效**（再次 `set_visible(true)` 会抢焦点）的坑；再补 `WS_EX_NOACTIVATE` 保证点击也不夺焦。
- 根视口是一个屏幕外 1×1 锚点：eframe 在根不可见时只跑 `logic` 不跑 egui pass，子视口必须靠"根可见或后代可见"才能渲染。
- glow 清屏色不透明——**全屏透明视口整片黑**。预告期"边缘渐暗"因此改用 4 条细边窗 + 整窗 `LWA_ALPHA` 半透明（点击穿透 + 不激活）。
- 屏幕外锚点在 Windows 上稳定（-26214 与系统最小化位姿同源），但要注意多显示器负坐标区的 DPI 取值。

### 2.4 检测层：平台 API 要怀疑

- `SHQueryUserNotificationState` 是官方"能否打扰"API，但 `RUNNING_D3D_FULL_SCREEN` 存在长期谎报；`SetForegroundWindow` 有前台锁；`with_active(false)` 只管首次显示；`GetSystemMetrics`/`MonitorFromWindow` 在混合 DPI 下要分清逻辑/物理像素。
- 键盘钩子（WH_KEYBOARD_LL）要过滤自动重复（低级钩子没有 KF_REPEAT，需自维护按下状态）和修饰键；回调只发时间戳立即返回。
- Win32 计时**包含睡眠时间**：跨睡眠的 dt 会灌爆计时器与用屏累计。

### 2.5 音频与通知

- rodio 的 `Mixer::add` 自动重采样到设备采样率（查源码确认，v0.1 审计里的"变调"担忧不成立）；`Decoder` 流式播放用户音频，不整包载入内存；无设备降级为静音，绝不 panic。
- 自绘通知界面按微软要求必须查询 `SHQueryUserNotificationState`；气球通知（NIF_INFO）未弃用但 TrayIcon 无法复用其 HWND，WinRT Toast 需 AUMID+开始菜单快捷方式——v0.5 选择自绘浮窗作为主视觉通道即源于此。

## 三、工程与流程经验

1. **配置即契约**：serde 全字段 `#[serde(default)]` + `sanitized()` 夹紧 + 解析失败改名备份 + v0.1 迁移保留用户自定义——旧配置永远不被静默销毁。
2. **纯逻辑核心可测**：`core.rs` 不碰 Win32/egui，时间由调用方注入，53 个测试锁住调度规则；v0.4→v0.5 的每次改动（长休息延后、睡眠阈值）都是改规则→改测试→全绿的循环。统计落盘用脏标记，测试不污染真实数据。
3. **CI 要从第一天就上**：edgedim 的测试断言在 GNU（本地）能推断通过、在 MSVC（CI）报错——本地绿 CI 红的工具链差异，靠"CI 从第一次提交就在"来兜底，而不是事后补。修复方式：断言用显式 `egui::vec2` 而非依赖推断。
4. **CI 环境≠本地环境**：choco 装 NSIS 后任务内 PATH 不刷新（用绝对路径调用）；日志下载接口未授权时 403（失败排查要靠 `gh run view --log-failed`，前提是已 `gh auth login`）。
5. **批处理脚本不要写中文**：UTF-8 中文 .cmd 在代码页切换完成前就被解析器拆碎，报一堆乱码命令。面向用户的脚本用 ASCII。
6. **依赖取舍要有依据**：rodio 裁掉解码器省 2 MB，后来为自定义音频再加回（需求变了就改）；rdev/single-instance 停更不引入；UPX 因杀软误报不用。
7. **仓库卫生**：649 MB 里 99.8% 是构建缓存——迁移按白名单复制；exe/安装包一律走 CI 产物，不进仓库。
8. **文档即决策**：CONTEXT.md（词汇表，统一"顺延/延后"等用语）、ADR（每个不可逆决策附来源 URL）、research/（六份带引用的调研）——事后排查和交接都从这里起步。

## 四、仍然有效的已知限制（截至 v0.5.0）

- 浮窗/严格遮罩只覆盖主显示器；多显示器在 Roadmap。
- "欢迎回来"闪屏的视觉样式未经人工截图确认（逻辑与计时已有单测）。
- 会话结束后显卡驱动残留 ~60 MB 私有内存（彻底解决需浮窗 Win32 自绘，见 Roadmap）。
- 完整电源/锁屏事件桥（WM_POWERBROADCAST / WTS 通知）未做，>10 分钟睡眠用 dt 阈值兜底。
- exe 未签名，首装有 SmartScreen 提示。
