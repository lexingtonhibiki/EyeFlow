# v0.3 变更报告：提示音可控性、全局热键与安装体验

> 日期：2026-09-08 · 用户反馈驱动：①提示音太短，听歌 / 看视频时根本察觉不到；②全局热键一直占用组合键，可能与已有软件冲突；③卸载务必无残留；④设置窗过高溢出任务栏。

## 1. 提示音音量与时长（新功能）

### 1.1 调研：背景音乐 / 视频下提示音为什么听不见，怎么办

| 来源 | 结论 | 对 EyeFlow 的落地 |
|---|---|---|
| **ISO 7731**(人机工程学—危险信号—听觉危险信号)：告警音必须与背景声**可区分**；脉冲时长与重复频率**不得与环境噪声的周期一致**；研究(Zera 2000, [PubMed](https://pubmed.ncbi.nlm.nih.gov/10828157/))显示 60 dB 背景噪声下最受偏好的告警音量是**背景之上 10~20 dB**，且不能强到引起惊吓(startle) | 提示音要"可察觉"靠三件事：与背景频谱/节奏错开、重复呈现、适度放大——而不是一味加大音量 | ① 音量上限 **200%**(基准峰值 0.4,放大后限幅 0.95)而非无限增强，避免惊吓；② EyeFlow 的提醒时机本身是三角随机分布的，天然避开与音乐节拍同步；③ 新增**时长 1~5 秒**，短图案以 0.15 s 间隔循环——"重复呈现"正是标准强调的可区分手段 |
| **WCAG 2.1 SC 1.4.7**(低背景音频，[W3C 官方](https://www.w3.org/WAI/WCAG22/Understanding/low-or-no-background-audio.html))：前景与背景声需要约 **20 dB** 的分隔；标准原文专门豁免了"**仅持续一两秒的偶发声音**"——这条豁免反向说明：一两秒内的短音在可感知性上是被标准"放弃"的 | 想让提示音穿透背景音乐，时长至少要脱离"一两秒偶发音"的范畴，或重复出现 | 时长默认 1 秒(安静环境足够)，设置界面明确建议听歌 / 看视频场景调到 **2~3 秒** |
| 场景事实：全屏看视频 / 打游戏时，EyeFlow 处于"游戏 / 不可打扰"状态，预告面板不可见，**声音是唯一通道** | 唯一通道的提示强度不应由与视觉通道相同的默认值决定 | 该场景下提示音**自动至少响 2 秒**(超出用户设定时长时取 2 秒下限)，设置文案中说明 |

### 1.2 实现
- `config.toml` 新增 `cue_volume_pct = 100`(50~200)、`cue_duration_secs = 1`(1~5)，越界值自动夹紧。
- `audio::render()`：先合成短图案，再以 0.15 s 静音间隔循环铺满目标时长，最后按百分比放大并限幅(±0.95)。
- 设置界面："提示音音量 50%~200%" 与 "提示音时长 1~5 秒" 两个滑条 + 场景建议文案；▶ 试听按当前音量 / 时长播放。
- 单元测试：目标时长精确达到、循环正确、音量单调放大、限幅生效、极端值不 panic。

### 1.3 其他被否决的方案
- **绕过系统音量直接改主音量**：违反微软 WASAPI 规范("应用不得修改全局音量，用户通过音量合成器控制")；EyeFlow 保持独立音频会话，用户可在音量合成器里单独调它。
- **TTS / 语音提醒**：对"护眼休息"这类非紧急提示过重，且无法穿透音乐(语音频段 300~3400 Hz 与人声音乐高度重叠)。

## 2. 全局热键可关闭

Ctrl+Shift+E 是操作系统级**全局独占**组合键——无论前台是什么应用都会触发，天然存在与用户已有软件(输入法、截图工具、播放器快捷键)冲突的可能。v0.2 把它写死不可关闭是不合理的。

- 设置 → 系统：复选框即时注册 / 注销(不需要重启)；注册失败(组合键被占用)时界面红字提示。
- 配置字段 `hotkey_enabled = true`；**v0.1 旧配置里关过热键的偏好会在迁移时保留**(实测你的旧配置就是 `hotkey_enabled = false`，迁移后保持关闭)。
- 关闭后托盘菜单的快捷键提示同步移除，"立即休息"菜单项照常可用。

## 3. 卸载无残留

实测 v0.2 卸载器：程序目录、自启键、卸载键、开始菜单全部清理 ✅，但 **`%APPDATA%\eyeflow\eyeflow.log` 残留** ❌。v0.3 卸载脚本补删日志(及 `.log.*` 轮转)后再移除目录。完整的卸载清单：exe + 卸载器(自删)、`config.toml` / `*.bak-*` / `stats.toml` / `eyeflow.log`、开始菜单、HKCU\Run 自启值、HKCU 卸载项、运行中的进程。

## 4. 设置窗尺寸

v0.2 默认 640×780 **逻辑像素**，在 150% 缩放下是 960×1170 物理像素——高超出 1080p 屏幕，正是"溢出任务栏"的原因。v0.3 改为**约 700×780 物理像素**(除以系统缩放换算逻辑尺寸，屏幕余量不足时自动收缩，内容走滚动)，布局间距整体收紧。

## 5. 安装器
- 静默安装(`/S`)不再弹出"现在启动吗？"(NSIS `MessageBox` 必须显式 `/SD IDNO` 才会在静默模式下取缺省答案——v0.2 的注释与实际行为不符，已修正)。
- 版本号默认值随 Cargo.toml 升至 0.3.0;CI 继续通过 `/DPRODUCT_VERSION` 注入。
